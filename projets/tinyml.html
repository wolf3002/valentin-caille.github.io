Reconnaissance de Chiffres Manuscrits

Système de reconnaissance MNIST embarqué sur microcontrôleur OpenMV H7 (STM32H743). CNN optimisé avec quantification Int8 et déploiement TensorFlow Lite Micro atteignant 99.45% de précision à 15-20 FPS en temps réel.

📋 Vue d'ensemble

Ce projet de TinyML (Machine Learning Embarqué) démontre l'intégralité de la chaîne de développement d'un système de reconnaissance de chiffres manuscrits pour microcontrôleur. Du dataset MNIST à l'inférence temps réel sur STM32, le projet couvre l'entraînement d'un CNN léger (117k paramètres), sa compression drastique via quantification Int8 (11.4x), et son déploiement sur caméra OpenMV H7.

Le système atteint 99.45% de précision sur MNIST et fonctionne à 15-20 FPS sur l'embarqué avec seulement 123 KB de mémoire Flash. Le projet illustre les défis du TinyML : optimisation du preprocessing pour MicroPython, gestion des contraintes mémoire, et validation de la généralisation sur des chiffres manuscrits réels.

🎯 Objectifs & Contraintes

Objectif : Classifier des chiffres manuscrits (0-9) en temps réel sur système embarqué contraint.

  • Précision >98% sur dataset MNIST
  • Modèle <2MB (contrainte Flash OpenMV H7)
  • Latence d'inférence <100ms (temps réel)
  • Compatible TensorFlow Lite Micro
  • Fonctionnement sur chiffres manuscrits réels (tracés au marqueur)

⚙️ Architecture CNN "Lightweight"

Modèle séquentiel personnalisé optimisé pour le ratio performance/poids, inspiré des architectures TinyML.

Structure du réseau

Entrée : 28×28×1 (Niveaux de gris, normalisés 0-1)
Bloc Conv 1 : Conv2D(16 filtres 3x3) × 2 + MaxPool2D(2x2) + Dropout(0.25)
Bloc Conv 2 : Conv2D(32 filtres 3x3) + MaxPool2D(2x2) + Dropout(0.25)
Bloc Conv 3 : Conv2D(32 filtres 3x3) + Dropout(0.25)
Classification : Flatten + Dense(64, ReLU) + Dropout(0.5) + Dense(10, Softmax)

Caractéristiques

  • 117,434 paramètres (458.7 KB en Float32)
  • Accuracy : 99.45% sur MNIST validation
  • Optimiseur : Adam (lr=0.001) avec ReduceLROnPlateau
  • Augmentation : Rotation (±15°), Translation (15%), Zoom (15%), Shear (15°)
  • 30 epochs d'entraînement sur 60,000 images

📦 Compression et Quantification

La quantification post-entraînement (Post-training quantization) avec représentative dataset convertit les poids et activations de Float32 vers Int8.

Gain de compression

  • Keras (.keras) : 1.4 MB (Float32) - Référence 1x
  • TFLite Standard : 458 KB (Float32) - Compression 3.1x
  • TFLite Quantifié : 123 KB (Int8) - Compression 11.4x

Validation : 0% de perte de précision après quantification (99.45% maintenu). Test exhaustif sur 10,000 images MNIST confirmé avec verify_full_pipeline.py.

🚧 Défis Techniques Majeurs

1. Format de sortie MicroPython

Problème : Le modèle TFLite sur OpenMV retourne array([[...]]) (liste 2D) au lieu d'une liste Python simple.
Solution : Extraction robuste avec conversion tolist() et vérification de la dimensionnalité.

2. Mismatch Preprocessing (Problème Majeur)

Symptôme critique : Toutes les prédictions retournaient "8" avec 99% de confiance, quel que soit le chiffre présenté.

Cause identifiée : Le preprocessing PC (Otsu, contours OpenCV, padding adaptatif) n'était pas compatible avec MicroPython sur OpenMV.

Solution : Simplification radicale du pipeline embarqué :

  • ROI statique 140×140 pixels (au lieu de dynamique)
  • Binarisation seuil fixe 128 (au lieu d'Otsu adaptatif)
  • Inversion immédiate (avant binarisation)
  • Détection blob native OpenMV find_blobs()
  • Padding fixe 10px (au lieu de 20% adaptatif)
  • Resize direct vers 28×28 sans transformations complexes

Leçons apprises

Simplicité > Complexité : Les algorithmes sophistiqués (Otsu, contours OpenCV) ne sont pas toujours nécessaires. Un seuil fixe bien choisi peut être aussi efficace sur embarqué.

Validation croisée essentielle : Tester le modèle TFLite sur PC avant déploiement permet d'isoler les problèmes (modèle vs preprocessing).

Quantification Int8 efficace : Compression 11.4x sans perte de précision démontre la pertinence du TinyML pour l'IA embarquée.
